## 一、项目概述

### 1.1 项目定位
PhotoStyle 是一款面向普通用户的 **图片风格转换工具**。核心理念是「把照片重新画成一页诗」——通过 AI 大模型将普通照片重新生成为具有艺术风格的手绘插画，而非简单的滤镜效果。

### 1.2 核心价值
- **零门槛**：用户只需上传照片，无需任何艺术基础
- **诗性表达**：将日常废片转化为有温度、有情绪的艺术作品
- **Skill 驱动**：通过 photo-revival skill 的提示词工程保证输出质量
- **多模型支持**：可对接千问、豆包、DALL-E 等多个大模型
- **跨端覆盖**：Web 端首发，后期平移微信小程序

### 4.1 图片上传模块

#### 功能描述
支持多种方式上传图片：拖拽上传、点击选择、粘贴剪贴板图片、从历史记录选择。上传前自动进行图片压缩优化。

#### 功能清单

| 编号 | 功能 | 说明 | 优先级 |
|------|------|------|--------|
| F-001 | 拖拽上传 | 拖拽图片到上传区域直接上传 | P0 |
| F-002 | 点击选择 | 点击上传区域打开文件选择器 | P0 |
| F-003 | 粘贴上传 | Ctrl+V 粘贴剪贴板图片 | P1 |
| F-004 | 格式支持 | 支持 JPG/PNG/WEBP/BMP 格式 | P0 |
| F-005 | 大小限制 | 单张图片最大 10MB，自动压缩至 2MB 以内 | P0 |
| F-006 | 尺寸压缩 | 自动压缩分辨率至最大 2048px（保持宽高比） | P0 |
| F-007 | 压缩进度 | 显示压缩进度和压缩前后对比 | P1 |
| F-008 | 上传进度 | 实时显示上传进度百分比 | P0 |
| F-009 | 图片预览 | 上传后立即显示预览 | P0 |
| F-010 | 多图管理 | 支持替换已上传图片 | P1 |
| F-011 | EXIF 处理 | 自动读取并处理 EXIF 旋转信息 | P1 |

#### 功能描述
Skill 引擎是 PhotoStyle 的核心，负责解析 photo-revival 的 SKILL.md 规则，结合图片分析结果和用户额外描述，生成结构化的提示词用于后续的图像生成。

#### 工作流程

### 4.3 LLM Provider 抽象层

#### 设计原则
- **可插拔**：新增模型只需实现 `ImageProvider` 接口
- **自动降级**：主模型失败自动切换备用模型
- **统一接口**：屏蔽各模型 SDK 差异
- **配置驱动**：通过配置文件管理各模型参数

#### Provider 接口定义

```python
class ImageProvider(ABC):
    """图像生成提供商统一接口"""
    
    @abstractmethod
    async def generate_image(
        self,
        prompt: str,              # 生成提示词
        reference_image_url: str,  # 参考图片 URL（用于图生图）
        options: ImageOptions      # 生成选项
    ) -> ImageResult:
        """
        生成图像
        
        Args:
            prompt: 生成提示词
            reference_image_url: 参考图片 URL
            options: 生成选项（比例、风格强度等）
            
        Returns:
            ImageResult: 生成结果（图片URL、消耗token等）
            
        Raises:
            ProviderTimeoutError: 生成超时
            ProviderAPIError: API 调用失败
        """
        pass
    
    @abstractmethod
    def get_provider_id(self) -> str:
        """获取提供商标识"""
        pass
    
    @abstractmethod
    def is_available(self) -> bool:
        """检查服务是否可用（API Key、配额等）"""
        pass
```

### 4.4 风格转换模块（核心双链路）

#### 功能描述
风格转换是系统核心，采用双链路架构：链路1 生成提示词（Skill Engine），链路2 生成图像（LLM Provider）。

#### 完整流程

```
┌─────────────────────────────────────────────────────────────┐
│                    风格转换完整流程                          │
│                                                             │

│  └──────────────────────┬──────────────────────────────┘    │
│                         │                                   │
│  ┌──────────────────────▼──────────────────────────────┐    │

│  │  ├── 压缩处理（确保大小合理）                       │    │
│  │  ├── 保存到数据库                                  │    │
│  │  └── 推送结果通知                                  │    │
│  └──────────────────────┬──────────────────────────────┘    │
│                         │                                   │
│  ┌──────────────────────▼──────────────────────────────┐    │
│  │  阶段 4：返回结果                                  │    │
│  │  ├── 返回结果图片 URL                              │    │
│  │  ├── 返回使用的提示词                               │    │
│  │  ├── 返回消耗的 Token/积分                          │    │
│  │  └── 前端展示结果                                  │    │
│  └─────────────────────────────────────────────────────┘    │
│                                                             │
│  总耗时预估：15-40 秒                                       │
```

## 十一、风险与应对

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|----------|
| 千问图像生成质量不稳定 | 中 | 高 | 多模型 fallback；人工校准 prompt 模板 |
| SKILL.md 生成效果不佳 | 中 | 高 | 迭代优化模板；收集用户反馈；人工校准 |
| 图片上传处理耗时 | 低 | 中 | 异步任务 + Redis 队列 + 进度轮询 |
| API Key 泄露 | 低 | 高 | 后端集中管理；环境变量；前端零暴露 |
| 微信小程序审核不通过 | 低 | 中 | 提前了解审核规则；准备软著；规避违规内容 |
| 成本超预期 | 中 | 中 | 用量限制；积分系统；本地测试使用低成本模型 |
| 高并发性能瓶颈 | 低 | 中 | Redis 缓存；异步队列；数据库读写分离 |
